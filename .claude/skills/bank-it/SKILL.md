# bank-it

Hard rule: any list of 3 or more items built in a response MUST be saved to a file in that same response. Save first, refine second. Unsaved work is lost work.

1. The moment a list, plan, or set of decisions reaches 3 items, write it to a file before continuing.
2. Save into the project (docs/ or notes/ folder, descriptive filename, not a date).
3. If a banked list changes later, update the same file. Do not create duplicates.
4. Never ask permission to bank. Banking is the default. Announce the file path in one short line and move on.
5. This applies to design decisions, content ideas, bug lists, task orders, and anything else that would hurt to lose.
